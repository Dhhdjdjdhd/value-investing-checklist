7. 문제 생겼을 때
────────────────────────────────────────────────────────────────
  [증상] 접속하면 404, 헤더에 x-render-routing: no-server
   → 앱 오류가 아니라 인스턴스가 없는 상태(슬립/재시작/배포중).
     UptimeRobot 모니터가 살아있는지 먼저 확인.

  [증상] 배포는 됐는데 특정 파일만 404
   → 그 파일이 커밋됐는지 확인: git ls-files <경로>
     GitHub 웹에서도 실제로 있는지 확인.

  [증상] 빌드 실패
   → Render 로그의 npm install / npm run build 구간을 볼 것.
     로컬에서 npm run build 를 돌려 재현되는지 먼저 확인.

  [Render 강제 재배포]
   대시보드 우측 상단 Manual Deploy
   → "Clear build cache & deploy" (빌드 캐시 문제일 때)

8. 분석 문서 갱신 절차  ★ 실적 발표 후 내재가치를 고칠 때 반드시 이 순서
────────────────────────────────────────────────────────────────

  [원본이 무엇인가 — 먼저 이것부터]

    02.종목분석/*.md        ← 판정의 원본. 이것이 진실이다.
                              frontmatter가 사이트의 탭 이름·요약을 만든다.
    public/reports/*.html   ← 시각 보고서. 같은 내용을 그림으로 보여주는 사본.
                              /dashboard 화면에 iframe으로 뜨는 것이 이쪽이다.

    ※ 둘이 어긋나면 사이트가 낡은 결론을 보여준다.
      2026-08에 실제로 겪었다 — MSFT의 08-14 점검 로그가 사본에 반영되지 않아
      사이트가 옛 판정을 표시했다. (경위는 lib/content.ts 상단 주석 참조)
      한쪽만 고치고 끝내지 말 것.


  [내재가치를 갱신할 때 — 고칠 곳이 3군데다]

  ① md 수정  (02.종목분석/<종목>_분석_<날짜>.md)
     - frontmatter: price / intrinsicValue / targetPrice / summary / verdict
     - 4단계 시나리오 표: 기준EPS · 성장률 · 할인율 · 터미널 가정 · 내재가치
       ※ 터미널 가정(종료 PER)을 반드시 먼저 정하고 계산할 것.
         이 칸이 비면 다음 갱신 때 같은 방식으로 재계산할 수 없다.
     - 접이식 "이 표의 숫자는 어떻게 나왔는가" 안의 숫자
     - "분할매수·내재가치 궤적 로그"에 갱신 사유와 함께 한 줄 추가
       (2회 연속 하향 = 매수 정지 규칙이 여기서 작동한다)

  ② HTML 수정  (public/reports/<티커>.html)
     - 밸류에이션 시나리오 표
     - 바(range-track)의 마커 위치 — left% = (가격 - lo) ÷ (hi - lo) × 100
       lo/hi는 바 아래 range-foot의 양끝 숫자
     - vicQuoteBar({ ... target: 새 목표매수가, cost: 평단 })
     - vicDcfBox({ eps0, g1, g2, r, per })   ← md 4단계와 같은 값이어야 함

  ③ 대조 확인
     md의 기본 시나리오와 HTML의 vicDcfBox 값이 같은지 눈으로 대조.
     (기준EPS · 할인율 · 종료PER 세 개만 맞으면 나머지는 자동 계산된다)

  ④ 커밋 → push → Render 자동 재배포 → 화면에서 최종 확인


  [새 종목을 추가할 때]

  1) 01.가치투자 체크리스트/01.종목분석_템플릿.md 를 복사해서 작성
     - frontmatter에 ticker가 있어야 사이트가 종목으로 인식한다
       (없으면 스크리닝 문서처럼 목록에서 제외된다)
  2) 보고서 HTML을 만들고 public/reports/<티커>.html 로 저장
  3) HTML 하단에 시세바·계산박스 스크립트 추가:
       <script src="/reports/_quotebar.js"></script>
       <script>vicQuoteBar({ ticker:'XXXX', lo:00, hi:00, target:00,
                             chart:'https://kr.investing.com/equities/...' });</script>
       <script src="/reports/_dcfbox.js"></script>
       <script>vicDcfBox({ eps0:0, g1:0, g2:0, r:0, per:0, perSrc:'기재' });</script>
     ※ 바에는 id가 필요하다:
       <div class="range-wrap" id="vicRangeWrap"> / <div class="range-track" id="vicTrack">
  4) 사이드바 탭은 자동 생성된다 (md의 frontmatter를 읽으므로 별도 등록 불필요)


  [공용 스크립트 — 고칠 때 한 곳만 보면 되는 것들]

    public/reports/_quotebar.js   실시간 시세 점 + 바 아래 한 줄 + 차트 팝업
    public/reports/_dcfbox.js     "계산 과정" 접이식 박스 (숫자는 매번 계산)
    app/api/quote/[ticker]        야후 시세 프록시 (60초 캐시, 장중에만 갱신)
    lib/content.ts                md를 읽어 탭 목록·상세 페이지를 만든다
