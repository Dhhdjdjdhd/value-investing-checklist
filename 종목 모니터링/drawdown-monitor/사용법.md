# 폭락 알림 모니터

사상 최고가 대비 낙폭이 기준선(-10/-20/-30/-50% 등)을 처음 넘거나, 하루에 크게 빠지면 Gmail로 알린다.
윈도 작업 스케줄러가 30분마다 `monitor.py`를 실행한다.

## 처음 설정
1. `설정화면 열기.bat` 실행
2. **메일** 탭: 보내는 Gmail · 받는 주소 · 앱 비밀번호(16자리) 입력 → 저장 → 테스트 메일 보내기
   - 앱 비밀번호: Google 계정 → 보안 → 2단계 인증 → 앱 비밀번호
3. **종목** 탭: 지금 점검 실행 → 현재가·낙폭이 표에 나오는지 확인
4. **스케줄 · 로그** 탭: 스케줄 등록 (30분마다)

## 알림 종류
| 종류 | 조건 |
|---|---|
| 폭락 | 최고가 대비 기준선을 처음 넘을 때 (같은 구간은 한 번만) |
| 급락 | 전일 종가 대비 하루 급락 기준 이상 하락 (거래일당 한 번) |
| 회복 | 구간을 해제 여유(기본 3%p)만큼 올라와 벗어날 때 — 메일 탭에서 끌 수 있음 |
| 신고가 | 낙폭을 지나 최고가를 다시 넘었을 때 |
| 가격선 | 종목 수정 화면의 "가격 알림선"(분석 문서의 내재가치·목표매수가·분할 가격) 아래로 처음 내려갈 때 |
| 공시 | SEC 8-K·10-Q·10-K 새 공시 (종목에 SEC CIK를 넣은 경우). 8-K 2.02면 "[실적 발표] R1~R3 점검할 차례" |
| 실적 D-3 | 다음 실적 발표 3일 전부터 한 번 (날짜를 안 넣으면 SEC 기록으로 추정: 작년 같은 분기 + 364일) |
| 이상 | 시세 조회 6회(3시간) 연속 실패 |

폭락·급락·가격선 메일에는 **하락 원인 판별표**가 붙는다 (원칙 ①-2) —
"비교 종목"(지수·동종 종목)의 오늘 등락과 고점 이후 등락을 나란히 놓고,
비교군 중앙값보다 3%p 이상 더 빠졌으면 "개별 요인 의심", 비교군도 같이 빠졌으면 "시장·업종 공통"으로 표시한다.
| 주간 요약 | 매주 월요일 아침 7시 이후 첫 점검 |

## v2 시뮬레이터 장부 (2026-10-23~)
체크리스트 v2(`01.가치투자 체크리스트/06.체크리스트_v2_정량규칙.md`)의 20종목 가상 장부를 함께 지켜본다.
장부 원본은 `public/reports/PORTFOLIO.html`의 데이터 블록이고, **고치는 건 분기 재점검뿐**이다 — 이 모니터는 읽기만 한다.

| 무엇 | 언제 | 메일 |
|---|---|---|
| 감시 목록 맞추기 | 매 점검 — 장부 종목을 `group: v2`로 자동 추가·해제 (처음 감시하는 종목은 현재 낙폭 구간을 기록만) | 없음 |
| 폭락·급락 | 다른 종목과 같음 (기준선 15/25/35/50%, 하루 −6%) | 종목별 |
| 실적 공시·실적 D-3 | v2 종목은 **하루 한 통으로 모아서** `[v2 실적]` | 하루 1통 |
| 그 밖의 공시 | v2 종목은 **중대 항목만** `[중대 공시]` (파산·사이버 사고·구조조정·손상·상장폐지 통지·감사인 변경·재무제표 신뢰 불가) | 종목별 |
| 비중 10% 초과 | 처음 넘을 때 한 번 `[v2 비중]` — 분기 재점검이 5%로 되돌린다 | 한 번 |
| 월간 성적표 | 매달 1일 아침 7시 이후 첫 점검 `[v2 월간]` — 시작 이후 수익률을 같은 날 같은 원화를 SPY에 넣은 경우와 비교 | 월 1통 |
| **분기 재점검** | **1·4·7·10월 2일 03:00** — 작업 `V2QuarterlyReview`(`체크리스트 검증/src/quarterly.py`): SEC 재무·주가 새로 고침(약 2시간) → 순위 재계산 → 30위 밖·관문 탈락 매도, 빈 칸 채우기, 10% 초과 5%로 → 보유 현황·감시판 HTML 갱신 → 커밋·푸시 → `[v2 분기 재점검]` 결과 메일 | 분기 1통 |

- 설정 화면의 **v2 장부** 탭: 총자산·수익률·비중·다음 실적·다음 재점검을 한눈에. "분기 재점검 지금 실행"으로 수동 실행도 된다.
- 분기 재점검이 중간에 멈추면 실패 메일이 온다. `py "체크리스트 검증/src/quarterly.py" --tag 2027Q1`로 다시 실행하면 끝난 단계는 건너뛴다.
- 정성 거부권(능력범위 밖·회계 의심)은 사람 몫 — 새로 들어온 종목을 빼려면 `체크리스트 검증/src/build_watch.py`의 `VETO`에 넣는다.
- 2026-10-23 전환 때 v1 감시판 종목(MSFT·GOOGL·V 등 목표가 대기용)은 **사용 끔**으로 돌렸다. 종목 탭에서 켜면 다시 감시한다.

## 가격선 갱신 — 실적 발표 후 내재가치를 고쳤을 때
"분석 문서와 자동 동기화"가 켜진 종목(MSFT·GOOGL)은 **md만 고치면 된다** (INFRA.txt 8번 순서 그대로).
다음 점검에서 `02.종목분석/`의 그 종목 최신 md를 읽어 내재가치·가격선을 맞추고, 값이 바뀌었으면 "[내재가치 변경]" 메일을 보낸다.
- 읽는 곳: frontmatter `intrinsicValue`·`targetPrice`, 4단계 표의 보수·낙관 행 굵은 금액(`**$352**`),
  "추가매수 계획"의 `$284 → $250 → $220` (없으면 목표매수가 −12%씩), 논제 점검 로그의 마지막 날짜
- 기본 내재가치 **2회 연속 하향**이면 메일에 "분할매수 금지 + 논제 재작성" 경고 (원칙 ③)
- 동기화가 켜진 종목은 설정 화면에서 가격선·내재가치를 고쳐도 다음 점검에서 md 값으로 돌아간다

## 데이터
- 시세: 사이트 API `/api/quote/<심볼>` (한국 종목은 네이버 실시간, 그 외 야후)
- 최고가·과거 통계: `/api/history/<심볼>?range=all` (전체 일봉, 하루 한 번 받아 `history_cache.json`에 저장)
  - 사이트에 range=all이 없으면 `range=max`(월봉)로 대신 계산 — 통계가 거칠어진다
- 금(GC=F)은 데이터가 2000년부터라 1980~2008년 하락기는 통계에 없다
